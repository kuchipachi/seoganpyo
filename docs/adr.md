## 전제 — 이 제약이 거의 모든 결정을 좌우했다

| 항목 | 값 |
| --- | --- |
| 예산 | **크레딧 $200 / 6개월** (2025-07 이후 신규 계정은 크레딧 소진형) |
| 만료 시 | 계정 **자동 폐쇄** (Paid 전환 안 하면) |
| 인스턴스 | t3.micro — RAM 913MiB + swap 1.5GiB |
| SLA | 없음 (포트폴리오·학습) |

일반적인 AWS 권장 구성을 그대로 따르면 **월 $48**이 나간다. 크레딧의 1/4이 매달 사라진다.
그래서 여러 곳에서 베스트 프랙티스를 **의도적으로 위반**했고, 왜 위반해도 되는지를 남긴다.

## 1. 비용 때문에 바꾼 것

| # | 항목 | 일반 권장안 | 우리 선택 | 절감 |
| --- | --- | --- | --- | --- |
| 1 | 로드밸런싱 | ALB | **Caddy on EC2** | $16/월 |
| 2 | 네트워크 | Private subnet + NAT | **Public subnet only** | $32/월 |
| 3 | DB 가용성 | Multi-AZ | **Single-AZ** | 인스턴스 비용 2배 |
| 4 | 도메인 | Route 53 | **nip.io** | $0.5/월 + 등록비 |
| 5 | 관측 | 자체 호스팅 유지 | **Grafana Cloud (SaaS)** | 913MiB 에 Prometheus 불가 |

### 프라이빗 서브넷을 안 쓴 이유 (#2)

DB 를 프라이빗에 두는 게 교과서 구성이다. 그런데 **EC2 도 프라이빗에 두면 인터넷으로
나갈 수 없다.** 우리 EC2 는 나가야 한다 — ECR, Mistral·Gemini API, 교수 크롤링,
Let's Encrypt 인증서 발급.

나가려면 NAT Gateway 가 필요하고 그게 월 $32 다.

> **퍼블릭 서브넷 = 공인 IP 가 있다**는 뜻이지 **누구나 들어온다**는 뜻이 아니다.
> 실제 차단은 보안그룹이 한다.

### 포기한 것

- **다중 AZ 이중화** — AZ 장애 시 서비스 중단
- **오토스케일링** — ALB 가 없어 수평 확장 불가
- **네트워크 계층 방어** — 보안그룹이 유일한 방어선

SLA 가 없으므로 감수한다. **실무라면 ALB·NAT 를 쓴다.**

## 2. 보안 — 비용과 무관하게 지킨 것

여기는 타협하지 않았다. 오히려 기본값보다 좁혔다.

| # | 항목 | 기본/흔한 방식 | 우리 선택 |
| --- | --- | --- | --- |
| 6 | EC2 → ECR 인증 | 액세스 키 | **인스턴스 역할** (키 없음) |
| 7 | DB 접근 | 서브넷 CIDR 허용 | **보안그룹 참조** |
| 8 | ECR 권한 | `FullAccess` | **리포지토리 3개 한정** |
| 9 | 비용 사고 방지 | 주의 | **IAM Deny 정책** |
| 10 | **CI 인증** | 액세스 키 + Secret | **GitHub OIDC** |
| 11 | **배포 경로** | SSH | **SSM Run Command** |
| 12 | **관리 포트** | 22번 개방 | **폐쇄** |
| 13 | **시크릿** | `.env` 평문 | **SSM Parameter Store** |

### 보안그룹 소스에 IP 대신 보안그룹을 쓴 이유 (#7)

```
SG-rds:  5432  ←  SG-web (그룹 참조)
```

| 방식 | 문제 |
| --- | --- |
| 서브넷 CIDR | 그 서브넷의 **모든** 인스턴스가 DB 접근 가능 |
| EC2 사설 IP | 재생성 시 IP 가 바뀌어 규칙을 매번 수정 |
| **그룹 참조** | EC2 가 바뀌어도 규칙 불변 ✅ |

### 액세스 키를 없앤 두 단계 (#6, #10)

작업 중 **실제로 액세스 키를 노출해 폐기한 적이 있다.** 그 경험이 이 결정의 배경이다.

```
1차: EC2 → 인스턴스 역할 (키 파일 없음)
2차: GitHub Actions → OIDC (레포에 Secret 없음)
```

둘 다 **임시 자격증명을 매번 받아 쓰고 버린다.** 저장할 게 없으니 유출될 것도 없다.

### 22번 포트를 닫을 수 있게 된 경위 (#11, #12)

SSH 배포는 22번 개방 + 개인키 보관이 필요하다. SSM 은 **EC2 가 AWS 로 나가서 명령을
받아오므로** 인바운드가 필요 없다.

부수 효과로 **가정용 동적 IP 때문에 보안그룹을 계속 갱신하던 문제**도 사라졌다.
작업 중 IP 가 바뀌어 SSH 가 막힌 적이 여러 번 있었다.

### SSM Parameter Store 의 한계 (#13)

`.env` 파일 자체는 남는다 — `docker compose` 가 `env_file` 로 읽어야 하므로.

**SSM 의 이점은 "저장소가 암호화되고 값 배포가 중앙화된다"**는 것이지 EC2 에서 평문이
사라지는 게 아니다. 다만 값을 바꿀 때 EC2 에 들어갈 필요가 없어졌다.

## 3. 운영 — 장애를 겪고 바꾼 것

| # | 항목 | 처음 | 바꾼 뒤 |
| --- | --- | --- | --- |
| 14 | 백엔드 라우팅 | 경로 나열 | **`/backend` 단일 prefix** |
| 15 | 헬스체크 | `/` (프로세스만) | **`/healthz` + 운영 풀** |
| 16 | 자동 복구 | 없음 | **autoheal + 루프 방지** |
| 17 | 알림 | 없음 | **CloudWatch → SNS → Lambda → Discord** |

### 경로 나열 → 단일 prefix (#14)

처음에는 `/api`, `/admin`, `/static` 을 하나씩 프록시 규칙에 적었다. 그런데
**`/auth`, `/history`, `/upload` 를 빠뜨려** 운영에서 아무도 로그인할 수 없었다(Critical).

더 근본적인 문제는 **`/admin` 이 백엔드 API 와 프론트 페이지가 같은 경로**라
나열 방식으로는 애초에 구분이 불가능했다는 것이다.

→ `/backend/*` 전용 prefix 로 통합. **새 라우터가 생겨도 누락이 구조적으로 불가능**해졌다.

### 헬스체크가 두 번 틀렸다 (#15)

**1차 오류** — `/` 는 DB 를 건드리지 않는다. 교착으로 21분간 멈췄는데 `healthy` 였다.

**2차 오류** — `/healthz` 를 만들었는데 **별도 연결 풀 + `async def`** 로 짰다.
교착은 DB 가 죽은 게 아니라 **앱 안쪽(스레드풀 + 운영 풀)이 막힌** 상태인데,
그 둘을 모두 우회해 교착 중에도 200 을 반환했다.

→ 실제 요청과 **같은 경로**(`def` + 운영 풀)로 수정. 복구 21분 → **약 50초**.

> 팀원이 재현 테스트(60 req/s × 60초)로 증명해 주지 않았다면 몰랐을 것이다.

### 자동 복구도 공짜가 아니다 (#16)

**Docker 의 restart 정책은 프로세스가 죽었을 때만 동작한다.** 살아서 멈춘 상태는
unhealthy 로 잡혀도 방치된다. autoheal 컨테이너로 메웠다.

그런데 이번엔 **근본 원인이 안 고쳐지면 무한 재시작**한다(실제로 108초 간격 2회 확인).
횟수 제한 옵션이 없어 외부에서 세는 스크립트를 붙였고, 임계를 넘으면 **autoheal 을
멈춘다** — 무한 재시작보다 멈춘 채로 사람을 기다리는 편이 조사에 유리하다.

### 알람은 적을수록 좋다 (#17)

**이 구성에서 실제로 터질 수 있는 것**만 4개로 제한했다. 울렸는데 문제없는 일이
반복되면 사람이 알람을 무시한다.

그중 **CPU 크레딧**이 가장 배운 항목이다. t3.micro 는 버스터블이라 크레딧이 소진되면
CPU 가 10% 로 강제 제한되는데, **사용률만 보면 "여유 있는데 왜 느리지?"** 가 된다.

> ⚠️ RDS 연결 수 알람(>40)의 근거를 처음에 "교착 감지" 로 적었다가 **틀린 걸 알았다.**
> 교착 때 앱 연결은 풀 크기인 15개가 전부라 40 을 넘을 수 없다. 목적을
> "연결 누수 감지" 로 재정의하고, 교착은 `/healthz` 와 Grafana 5xx 룰이 담당하도록 나눴다.

## 정리 — 이 기록의 의미

결정 하나하나보다 **"제약 안에서 무엇을 포기하고 무엇을 지켰는가"** 가 중요하다.

- **비용** 때문에 가용성·확장성을 포기했다 — SLA 가 없으니 합리적이다
- **보안**은 비용과 무관하게 지켰고, 오히려 기본값보다 좁혔다
- **운영**은 겪은 장애마다 고쳤고, 고친 것이 **실제로 동작하는지 일부러 장애를
  일으켜 확인**했다

마지막이 가장 크게 배운 부분이다. 설정을 넣는 데는 30분, 동작을 확인하는 데는
그보다 오래 걸렸고, **확인 과정에서 처음 설계가 틀렸다는 것도 두 번 드러났다**
(헬스체크 #15, RDS 알람 근거 #17).

> **장애 하나를 재현했다고 그 계열 전체가 검증된 것은 아니다.**
> DB 네트워크 차단과 연결 풀 교착은 증상이 비슷해 보이지만 막히는 지점이 다르다.
